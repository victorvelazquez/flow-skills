# Simplify Flow Commit and PR delivery

## Goal

Manual `/flow-commit` and `/flow-pr` invocation authorizes the requested local commit or PR push/create/update without a second prompt in Pi or OpenCode. Each command uses one named agent with independently configurable model. Return verified result or a precise blocker; never merge. Preserve the copyable, inert `JIRA COMMENT` after verified PR publication; never call Jira.

## Scope and safety

- Keep shared Flow runtimes, PR base-resolution rules, intent validation, result verification and Jira output contract. Do not reset the dirty worktree or discard unrelated Flow PR work.
- Pi: prompt routes once to named executing agent; remove custom parent approval, evidence pager and tests only after their references are gone. The agent reads the skill and owns the workflow, with no extra TUI or confirmation. Parent routing still uses its active model for one turn.
- OpenCode: existing single agents remain; execution changes from `ask` to direct permission. PR base/fork ambiguity stops with an actionable blocker rather than asking mid-flow.
- Model profiles remain per-agent; model selection is independent of Pi `/model`. Do not invent a model choice or alter shared runtime behavior for this simplification.
- No real commit, push or PR as a verification probe. Do not bypass host-enforced security dialogs. Back up untracked Pi-only files before irreversible deletion. Preserve history task records.
